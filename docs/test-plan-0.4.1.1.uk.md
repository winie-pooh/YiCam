# План тесту 0.4.1.1
Звіт: поширений лог (екран Probe → «Поділитися логом») і відповіді на пункти ЗАПИШИ.
1. Чистий старт: повністю закрий додаток, вимкни й увімкни камеру. Підключись, відкрий «Файли на камері», НЕ відкриваючи пряму трансляцію. Завантаж фото. Воно має завантажитися. У лозі знайди рядки «[DL] ... waking the camera web server (msg_id 259 none_force)», «web server wake-up accepted» і «[HTTP] answer 200» (або 206). ЗАПИШИ, чи завантаження спрацювало і що відповіло пробудження.
2. Якщо завантаження з пункту 1 не вдалося: ЗАПИШИ рядки [DL]/[HTTP] з лога (код відповіді або помилку зʼєднання) — це саме та інформація, якої не вистачало до 0.4.1.1.
3. Завантаж коротке відео. У лозі є «[DL] ... done, N bytes in M ms». ЗАПИШИ N і M (це дає реальну швидкість HTTP).
4. Відкрий пряму трансляцію, потім екран файлів і завантаж інше фото. Трансляція зупиняється, завантаження працює. ЗАПИШИ, чи було щось інакше, ніж у пункті 1.
5. Почни запис відео на камері (з екрана трансляції), потім спробуй завантажити файл під час запису. ЗАПИШИ, що відповіло пробудження (очікується rval -21) і чи спрацювало завантаження, або який рядок [DL]/[HTTP] пояснює збій.
6. Лістинги: відкрий папку з багатьма файлами. У лозі є «[FILES] <папка>: N files». Вимкни Wi-Fi камери й натисни «Оновити»: у лозі зʼявляється рядок [FILES] [ERR], а на екрані — помилка. ЗАПИШИ обидва.
